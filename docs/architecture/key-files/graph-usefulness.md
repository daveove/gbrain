# Graph measurement and guarded relation receipts

- `src/commands/graph-usefulness-dispatch.ts` handles local `graph measure`, `stats`, `relations`, and `retrieval-proof` before generic flag validation. Help needs no engine. Thin clients refuse these host-only commands; bare `graph <slug>` retains the existing traversal dispatcher.
- `src/commands/graph-usefulness.ts` validates scope, limits, manifest arguments and explicit apply confirmation. Read commands use the existing local federation resolver. Relation writes require concrete active sources and declared write vocabulary.
- `src/core/graph-usefulness/fingerprint.ts` captures page/source identity, retrieval-visible links, content/chunks, ranking inputs and the optional search pin in one SQL statement. Graph and retrieval hashes use separate domains; source incarnation and semantic knowledge revision prevent identity reuse.
- `src/core/graph-usefulness/paged-runner.ts` walks source-qualified page IDs with bounded keysets. Format 6 stores the source incarnation and commit-ordered generation from one snapshot. It binds the normalized union-source scope and counts links by deterministic endpoint ownership without retaining link IDs. It validates the token around batches and completed checkpoint reuse; missing sources and old formats refuse. Every source is revalidated after a multi-source walk.
- `src/core/graph-usefulness/schema.ts` owns the shared trigger DDL used by fresh Postgres/PGLite schema and additive migration 170. Deferred transaction-coalesced generation updates observe pages, chunks, aliases, takes, links and incident foreign endpoints/origins. Selected search configuration uses a separate singleton generation and a typed pending kind. The atomic installation marker expires preexisting legacy generations once; fresh corrected schema sets the marker without fabricating legacy changes. Modern migrations 146 and 147 retain their existing identities.
- `src/core/graph-usefulness/relation-manifest.ts` locks source and endpoint rows, rechecks active-source and no-incident-edge guards, and inserts declared unmanaged link producers. Reserved receipts record owned link IDs and row xmin before acceptance. Compensation only removes unchanged rows owned by this apply; concurrent replacement remains intact.
- `src/core/graph-usefulness/retrieval-proof.ts` uses live hybrid search, never the query cache. `search-pin.ts` snapshots only the documented search inputs. The existing search-mode snapshot seam and a typed internal proof snapshot hold configuration across questions; before/after fingerprints and source-qualified commit generations detect persistent and reverted writes without treating unrelated source deletion as a mutation. Incident outbound and mention changes conservatively refuse a proof even when the current ranking fingerprint excludes those edges; this shares the graph epoch instead of creating a second ranking-only registry. No proof pin is exposed through operation or MCP parameters.
- `types.ts`, `limit.ts`, `junk-classify.ts` and `measure.ts` define manifest/receipt shapes, positive bound validation and graph report predicates. `contains` is write vocabulary only, with no extraction inference rule.

Coverage: `test/graph-usefulness.test.ts`, `test/paged-graph-runner.test.ts`, `test/graph-source-watermark.test.ts`, `test/source-mutation-upgrade.test.ts`, and `test/graph-fingerprint-format.test.ts` exercise receipts, transaction/coalescing, checkpoint invalidation, modern identity, migration replay, timestamp settings and pinned search behavior.
